## Route Scope

Workers route:

- `/$orgSlug/c/$connectionId/workers`

This view combines topology visualization and a component-aware worker detail table.

## Topology Model

When `DURABULL_PROCESSOR_COMPONENTS` is configured, the default graph renders:

- Redis connection
- deployed processor components
- configured processor workloads when a component is focused
- observed-job and connected-worker evidence for each workload

The component overview remains visible even when no jobs from a configured
workload occur in the current sample. Workloads missing from the configuration
appear under **Unassigned**, making configuration drift visible.

The queue view remains available and renders:

- Redis node
- Queue nodes
- Worker nodes per queue

Queues and workers are sorted for stable layout. Edge styling reflects queue and worker activity.

## Worker Status Rules

Durabull classifies workers as active/idle using idle time.

Current UI rule:

- `idle <= 5000ms`: active
- `idle > 5000ms`: idle

## API Endpoint

- `GET /api/c/:connectionId/workers`

Returns:

- configured processor-component metadata
- worker list with queue context
- queue rollups (worker count, pause status, active/waiting counts, and observed processors)
- queue-level pagination metadata

## Practical Use Cases

- Verify worker registration after deployment changes.
- Detect queues with waiting jobs but no workers.
- Confirm whether queue pause state is intentional.
